# Forgematica 补料接管（Schematic Restock）

**版本：1.0.0 ｜ Minecraft 1.21.1 ｜ NeoForge 21.1.x**

加载好原理图（投影）之后，这个模组替你干两件最烦人的活：

1. **一键补料**——按 V+M，它只翻你标记过的材料箱，把缺的货搬进背包；
   箱里现货不够的，自动展开**多段工作台合成**（原木 → 木板 → 木棍 → 工作台这种链条）；
2. **安全打印**——按 V+U，服务端逐格放置原理图，限流、限距、缺料只延后不误判，
   放不下的格子永远留在原地等你补料，绝不吞料。

全程**先模拟、后执行**：任何一个动作都要"取得出、放得下"两头都成立才动真格，
物品永远不会掉地上、不会被复制、也不会被黑。

## 安装

| 依赖 | 必装？ | 说明 |
| --- | --- | --- |
| NeoForge | ✅ 必装 | 21.1.x（MC 1.21.1） |
| Forgematica | ✅ 必装 | 投影的 NeoForge 移植。缺口清单、幽灵方块都来自它，没装启动时会明确提示 |
| MaFgLib | ✅ 必装 | Forgematica 自己的基础库，同样会点名提示 |
| Curios | ⭕ 可选 | 装了才会把「饰品栏里背挂的背包」当成存放处（优先级 B） |
| 精妙背包 / Sophisticated Core | ⭕ 可选 | 手持 / 背挂的精妙背包会被自动收进优先找货、也优先投料 |

把 `schematic_restock-1.0.0.jar` 放进 `mods` 文件夹即可。
**单机**只装客户端；**联机**时客户端和服务端都要装，而且必须是同一个 jar
（网络协议带版本号，两端不一致会在进服握手时被直接拦下并说明原因）。

首次启动会在 `.minecraft/config/` 下生成 `schematic_restock-common.toml`，见下文。

## 快捷键（都在"按键设置 → 补料接管"里可改）

组合键的按法是：**先按住 V 不放，再按主键**。

| 组合 | 作用 |
| --- | --- |
| **V + M** | 补料接管。把所有缺料按「手持容器 → 饰品栏背挂 → 随身潜影盒 → 背包」的优先级搬进你身上；箱里现货不够的自动走工作台合成。你身上已有的件数会先扣掉，所以**同一批料反复按不会多拿**（幂等） |
| **V + U** | 自动建造：开始 / 暂停 / 继续。空闲时按下=上传计划开工；施工中按下=暂停；暂停中按下=继续 |
| **V + Y** | 取消自动建造。**已经放下去的方块不回滚**，只收掉后续计划 |

补料和建造互相让路：建造卡缺料时直接按 V+M，施工会自动暂停，补完自动续工，不用你管交接。

HUD 会在屏幕左上角显示当前缺口、阶段（A 搬运 / B 合成）、进度条、缺料与延后计数；
真卡住（60 秒一格都没落地）会自己收场并说明原因，不会无限刷"已开始"。

## 标记签怎么用

合成表：`data/schematic_restock/recipe/mark_wand.json`（也放在创造"建筑方块"页）。

| 操作 | 效果 |
| --- | --- |
| **右键** 容器 | 标记 / 取消**材料箱**（补料只从标过的箱子里拿）。手持标记签时右键**不会**打开箱子界面；右键到泥土石头这类非容器只给一句红字提示，什么都不做 |
| **Shift+右键** 点两下 | 框选一个立方区域，整片批量标成材料箱（单次最多 64 个容器，超了会拒绝整批并提醒你缩小范围） |
| **Shift+左键** 容器 | 标记 / 取消**输出箱（溢出箱）**：只进不出，专门吃合成超发的产物和背包塞不下的余料 |

箱子、木桶、潜影盒以及带物品能力的模组储物方块都可以标。拆掉的箱子会自动从名单里掉出去。

## 配置文件 `config/schematic_restock-common.toml`

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `autobuild.blocksPerTick` | 8 | 每 tick 最多放几块（另有 4ms 时间闸门，先到算哪个） |
| `autobuild.distanceLimit` | 64 | 距离闸门（格）。超出只延后不判死，走近了继续 |
| `autobuild.placeFluids` | true | 是否允许放流体（永远排在所有固体之后；关掉则流体格被跳过并在收尾说明） |
| `autobuild.replacePolicy` | `AIR` | 覆盖策略：`AIR` 只填空气 / `SOFT` 含草、雪、水等原版可替换 / `MISMATCH` 不对就覆盖 |
| `restock.craftMaxDepth` | **4** | 递归合成最大深度（原木→木板→木棍→工作台 = 3 层）。模组整合包的中间件链条普遍要 4 层，所以默认就是 4；链条更长（染色床、机器零件、嵌套组件）可提到 5~6 |
| `restock.searchRadius` | 16 | **兜底搜索半径**：只在"一个材料箱都没标"时生效——临时借用玩家半径 N 格内实测到的容器取料，并在聊天栏说明。0 = 关掉兜底 |

改完这个文件要**重启游戏**才生效（它是启动时读一次的那种配置）。文件被删掉、某一行写坏、
或者数字超出范围，模组都不会崩：那一行自动退回上表的默认值/边界值。
`/matfill status` 里会写明当前这一项是"配置文件"说了算还是"命令覆盖"说了算。

游戏内命令是快捷修改方式（**只改内存、不写回文件**）：

```
/matfill build replace <air|soft|all>   改覆盖策略（下一份计划生效）
/matfill build fluids <on|off>          改流体开关
/matfill build start|cancel             等价于 V+U / V+Y
/matfill status                         客户端/服务端两边的建造状态对照
/ghostlog on|off                        排障日志（写 logs/latest.log，搜 matfill/ghost）
```

## 常见问题（FAQ）

**Q1：为什么去皮原木/切制方块"无法合成"？**
补料只认**工作台（含投影认可的普通）配方**。去皮原木要靠原木+木头合成这类链条，
原版并没有"工作台直接合成去皮原木"的配方，所以它会被列进「查无工作台配方」清单并跳过。
**对策**：提前把这类需工具加工的料备好放进材料箱，或者加深配置里的 `craftMaxDepth`（默认已给到 4 层）。
这类物品 HUD 会显示"无配方 N 种"，收尾聊天栏会点名列出。

**Q2：为什么方块没放下去？**
先看 HUD 的"缺料 / 延后"计数，对号入座：
- **背包没材料** → 按 V+M 补料，补完自动续建（这是最常见的一种）；
- **那一格被别的方块挡着** → 默认覆盖策略是"只填空气"（`AIR`），先用 `/matfill build replace all` 或改配置再重按 V+U；
- **黑名单 / 无法用物品放置的方块**（火、红石线、结构空位等）→ 会记进"无对应物品"，这是设计行为，手工处理；
- **距离超出 `autobuild.distanceLimit`** → 走近一点就继续。

**Q3：箱子明明有货，V+M 却显示"未识别到缺口"？**
先确认投影已经加载了原理图并且 L 键能看到缺口清单——本模组读的就是那一份数据。
再确认你**标记过材料箱**；一个都没标时只会走 16 格兜底半径，储物墙离得远就标上箱再按。

**Q4：建造到一半想改图纸 / 换图纸？**
按 V+Y 取消（已放下的方块保留），移动或删除投影的放置，再按 V+U。
放好的格子在下一份计划里会被"现状已经对"闸门直接跳过，不会二次扣料。

**Q5：它会动我投影（Forgematica）的设置吗？**
不会。对投影**只读不写**；唯一的双向交互是把投料件数同步回投影的 L 键缺口显示，
随时可用 `/matfill unsync` 还原成投影原始缺口。

**Q6：服务器要装吗？**
要。放置与搬运都发生在服务端（服务端逐格 `setBlock`），只装客户端没用；
两端 jar 必须是同一份，旧客户端连新服务端会在握手阶段被拦下并看到明确原因。

## 已知边界

- 原理图里箱子/告示牌等**方块实体的内容一律不搬**：放出来就是空箱子、空白牌子。
  这一条同时防崩与防复制，收尾会说明这类格子放了多少。
- 床、门这类双格方块只收一次料（第二格免费）；花盆+植物按"空花盆 1 + 植物 1"两样料收。
- 旁观模式下自动建造会被停手（放下去的方块保留）。
- 一次受理 128 种材料、最多翻 96 个标记容器；再大的工程请分区分批。
